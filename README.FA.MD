# صف اولویت پویا

[English guide](README.MD)

یک صف اولویت ساده در پایتون با پنج سطح دارای ظرفیت محدود، انتقال ورودی به سطح پایین‌تر هنگام پر شدن صف و ارتقای پویا میان سطوح مجاور. این پروژه فقط از کتابخانهٔ استاندارد پایتون استفاده می‌کند.

## فایل‌های پروژه

| فایل | کاربرد |
| --- | --- |
| `dynamic_queue.py` | پیاده‌سازی کلاس `DynamicPriorityQueue`. |
| `example.py` | مثال قابل اجرا برای استفاده از صف، شامل ۱۰۰ داده با اولویت تصادفی. |
| `tests/test.queue.py` | تست‌های افزودن داده، طول صف، انتخاب اولویت، صف خالی و انتقال هنگام پر شدن ظرفیت. |

## پیش‌نیازها

پایتون نسخهٔ ۳٫۶ یا جدیدتر. نیازی به نصب کتابخانهٔ جانبی نیست. دستورهای زیر را از پوشهٔ اصلی پروژه اجرا کنید.

## شروع سریع

```python
from dynamic_queue import DynamicPriorityQueue

queue = DynamicPriorityQueue()

queue.enqueue("Background task", priority=1)
queue.enqueue("Urgent task", priority=5)

print(len(queue))       # 2
print(queue.dequeue()) # Urgent task
print(queue.dequeue()) # Background task
print(queue.dequeue()) # None
```

## نحوهٔ کار

اولویت **۵ بالاترین** و اولویت **۱ پایین‌ترین** سطح است. در هر سطح، داده‌ها به ترتیب ورود خارج می‌شوند؛ یعنی اولین ورودی، اولین خروجی است.

### ظرفیت‌های پیش‌فرض

| اولویت | حداکثر تعداد داده |
| --- | --- |
| ۵ | ۱۵۰ |
| ۴ | ۲۰۰ |
| ۳ | ۳۰۰ |
| ۲ | ۳۵۰ |
| ۱ | ۴۰۰ |

### افزودن داده و پر شدن ظرفیت

متد `enqueue(item, priority=5)` ابتدا سطح درخواستی را بررسی می‌کند. اگر آن سطح پر باشد، سطوح پایین‌تر را به‌ترتیب امتحان می‌کند. در صورت ذخیره شدن داده، مقدار `True` و در صورت پر بودن سطح درخواستی و تمام سطوح پایین‌تر، مقدار `False` برمی‌گرداند. سطوح بالاتر بررسی نمی‌شوند.

### برداشتن داده و ارتقای اولویت

متد `dequeue()` قدیمی‌ترین داده را از بالاترین سطح غیرخالی خارج می‌کند. اگر کل صف خالی باشد، مقدار `None` برمی‌گرداند.

پیش از هر خروج، آستانه‌ای بر اساس تعداد فعلی داده‌های همان سطح محاسبه می‌شود:

```python
threshold = max(1, math.ceil(queue_length / 3))
```

هر سطح شمارندهٔ خروج مستقل دارد. وقتی شمارندهٔ سطح فعال به آستانه برسد، صفر می‌شود. اگر سطح بلافاصله پایین‌تر داده‌ای داشته باشد، قدیمی‌ترین دادهٔ آن به انتهای سطح فعال منتقل می‌شود. آستانه در هر فراخوانی دوباره محاسبه می‌شود و اندازهٔ یک دستهٔ ثابت نیست. ارتقا از سطح خالی عبور نمی‌کند؛ بنابراین در صورت ورود مداوم داده‌های با اولویت بالا، رسیدگی نهایی به همهٔ سطوح پایین‌تر تضمین نمی‌شود.

عبارت `len(queue)` مجموع تعداد داده‌های موجود در تمام سطوح را برمی‌گرداند.

## ظرفیت‌های دلخواه

یک دیکشنری شامل هر پنج سطح اولویت به سازنده بدهید:

```python
queue = DynamicPriorityQueue(
    max_capacities={1: 50, 2: 50, 3: 50, 4: 50, 5: 50}
)
```

اولویت باید عدد صحیح بین ۱ تا ۵ و ظرفیت‌ها باید عدد صحیح نامنفی باشند. پیاده‌سازی فعلی این ورودی‌ها را اعتبارسنجی نمی‌کند. اگر دیکشنری ظرفیت را ندهید یا دیکشنری خالی بدهید، ظرفیت‌های پیش‌فرض استفاده می‌شوند.

## اجرای مثال

فایل `example.py` مثال اجرایی پروژه است:

```bash
python3 example.py
```

این فایل ابتدا افزودن و برداشتن داده را نشان می‌دهد، سپس با ظرفیت‌های دلخواه، ۱۰۰ داده با اولویت تصادفی اضافه و خارج می‌کند. پیام‌های وضعیت داخل حلقه‌ها و برای هر عملیات چاپ می‌شوند؛ مقدار داده‌های خارج‌شده چاپ نمی‌شود.

## اجرای تست‌ها

فایل `tests/test.queue.py` شامل چهار تست با ماژول استاندارد `unittest` است. در مک یا لینوکس اجرا کنید:

```bash
PYTHONPATH=. python3 tests/test.queue.py
```

در PowerShell ویندوز:

```powershell
$env:PYTHONPATH = "."
python tests/test.queue.py
```

تنظیم `PYTHONPATH` امکان وارد کردن ماژول پوشهٔ اصلی را از داخل پوشهٔ `tests` فراهم می‌کند. این فایل را مستقیم اجرا کنید؛ نام فعلی آن، یعنی `test.queue.py`، برای کشف خودکار استاندارد تست‌ها با `unittest` مناسب نیست. اجرای موفق پیام‌های `Ran 4 tests` و `OK` را نمایش می‌دهد.

## ثبت رویدادها

برای مشاهدهٔ رویدادهای صف، لاگ پایتون را تنظیم کنید:

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(message)s",
)
```

لاگر `DynamicPriorityQueue` جزئیات ورود و خروج را در سطح `DEBUG`، ارتقا را در سطح `INFO`، پر شدن ظرفیت را در سطح `WARNING` و کنار گذاشتن داده را در سطح `ERROR` ثبت می‌کند. این لاگر دارای `NullHandler` است و تنظیمات لاگ برنامه را خودش تعیین نمی‌کند.

## نکات استفاده

- صف سازوکار همگام‌سازی برای دسترسی هم‌زمان ندارد.
- مقدار `None` نشانهٔ صف خالی نیز هست؛ اگر باید داده را از نتیجهٔ خالی تشخیص دهید، این مقدار را در صف ذخیره نکنید.
- تست‌های موجود رفتارهای پایه را پوشش می‌دهند، نه تمام ورودی‌ها و حالت‌های زمان‌بندی را.
